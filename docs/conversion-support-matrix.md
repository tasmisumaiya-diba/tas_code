# Six-direction conversion support matrix

This matrix describes the current converter contract, not the full syntax accepted by JavaParser/Javac or Clang. “Fully supported” means the listed subset is handled in the current implementation and covered by tests; it does not mean the entire source language feature family is complete. Unsupported constructs should fail with a parser or conversion diagnostic. See the linked audits for syntax-level detail.

| Direction | Fully supported, within tested subset | Partially supported | Unsupported or unsafe in this IR |
|---|---|---|---|
| C → C++ | Scalar free functions, supported expressions, conditionals and loops, one-dimensional local arrays, recognized `printf`/`scanf` patterns, and selected literal-valued enums. | Preprocessor is limited to recognized headers and simple object-like literal macros; runtime-sized local arrays are represented by `std::vector`; only tested integer/format cases are accepted. | Pointers, pointer arithmetic, function pointers, structs/unions, globals, `switch`, `goto`, arbitrary macros, and many C declarators. See [C-to-C++ audit](c-to-cpp-support.md). |
| C → Java | Tested scalar functions, expressions, control flow, one-dimensional arrays, `main` normalization, selected `printf` and `scanf` patterns. | C numeric truth values are rewritten to Java boolean comparisons; formatted I/O is restricted to checked specifiers; C `long`, `char`, overflow, and undefined behavior have platform-sensitive limits. | Pointer and address semantics, global state, aggregate layouts, C enums, `goto`, arbitrary preprocessor behavior, and operations without a Java semantic equivalent. |
| C++ → C | The shared scalar free-function subset (expressions, blocks, conditionals, and loops) when written in syntax accepted by both restricted parsers. | Selected primitive array and standard-library spellings may parse, but C++-specific constructs are rejected when the C generator cannot represent them; use C compiler validation for generated output. | `std::cout`/`std::cin` (diagnosed for C output), general `std::string`/`std::vector`, class/object lifetime, references, templates, exceptions, inheritance, RAII, smart pointers, lambdas, overloaded operators, and namespaces. |
| C++ → Java | Tested scalar functions, supported expressions/control flow, selected arrays and strings, stream output/input patterns, and supported `main` conversion. | `std::string`/`string` map to Java `String` for documented methods and value operations; arrays and stream token behavior are restricted. | Templates, object lifetime/RAII, references/pointers, exceptions, inheritance, lambdas, arbitrary STL containers/algorithms, and C++ behavior that depends on deterministic destruction or undefined behavior. |
| Java → C | Tested static function subset, primitive values, supported expressions/control flow, one-dimensional arrays, `main` normalization, and selected print/println forms. | String output and array shapes are restricted; Java `main` is accepted only when it does not use command-line arguments; source/target character and integer-width behavior can differ. | General objects and class state, identity and aliasing, constructors/instance methods, inheritance, generics, exceptions, collections, lambdas, null references, UTF-16-dependent behavior, and garbage-collected lifetime semantics. |
| Java → C++ | Tested static function subset, primitive values, supported expressions/control flow, one-dimensional arrays, selected string operations, and simple primitive-field data classes. | Arrays map to `std::vector`; Java `byte`/`long` and string helpers use explicit mappings; simple class layout does not preserve general Java object identity. See [Java-to-C++ audit](java-to-cpp-support.md). | Constructors with behavior, general instance methods, dynamic dispatch, inheritance/interfaces, generics, collections beyond arrays, exceptions, lambdas, null, nested classes, and arbitrary Java library/JVM behavior. |

## Status meanings and semantic limits

- **Fully supported** is scoped to the constructs named in that row and exercised by the existing positive/negative/compiler tests. Compiler success verifies syntax and typing, not program equivalence.
- **Partially supported** means only a named spelling, type, or behavior pattern is converted. A wider language feature must be rejected or may remain outside this converter's parsing grammar.
- **Unsupported** means conversion must not claim success. Where source and target models differ fundamentally—pointer aliasing, Java object identity/null/GC, C++ lifetime/RAII, or undefined/implementation-defined behavior—the safe outcome is a diagnostic unless a future IR and runtime model can preserve the behavior.

The opt-in `clangLowering: true` path is a separate incremental route for a small C/C++ AST subset. It does not expand the default six routes yet. Its current status and AST-level coverage are documented in [the Clang frontend guide](clang-semantic-frontend.md).
